# 注意力 03：矩阵与形状

**目标**：看懂任何一段注意力代码。方法只有一个：**每一行都能说出每个张量的形状**。形状对了，大部分 bug 在运行前就能发现。

**配套**：[形状追踪器](demo/index.html)（拖参数看形状与内存、猜形状）· 上一篇：[注意力 02：手算](../attn-02-hand-calc/)。

**前置**：[注意力 02：手算](../attn-02-hand-calc/) 里的矩阵乘法。

---

## 第 1 层 · 一句话

真实代码里，输入是一个形状为 `[B, n, d]` 的三维张量；注意力的全部步骤，就是对它做 reshape、transpose 和矩阵乘法，最后仍得到 `[B, n, d]`。

## 第 2 层 · 白话

手算时我们只处理一句话（`[n, d]`）。真实训练一次处理很多句话，所以前面多一个“批”维度 `B`；多头又要把一个大向量切成几份，所以多出一个“头”维度 `h`。形状变来变去，本质只是在**整理数据的摆放方式**，让每个头、每个句子能同时并行计算。

---

## 第 3 层 · 追踪一次完整的多头注意力

记号：`B` 批大小，`n` 序列长度，`d` 即 $d_{model}$，`h` 头数，`dk = d/h`。

| 步骤 | 操作 | 形状 |
|---|---|---|
| 0 | 输入 X | `[B, n, d]` |
| 1 | `Q = X @ W_Q`（K、V 同理，W 是 `[d, d]`） | `[B, n, d]` |
| 2 | reshape：把最后一维 `d` 拆成 `h × dk` | `[B, n, h, dk]` |
| 3 | transpose：把头换到前面 | `[B, h, n, dk]` |
| 4 | 分数 `S = Q @ Kᵀ / √dk`，其中 Kᵀ 为 `[B, h, dk, n]` | `[B, h, n, n]` |
| 5 | softmax（沿最后一维） | `[B, h, n, n]` |
| 6 | `A @ V` | `[B, h, n, dk]` |
| 7 | transpose 回来 | `[B, n, h, dk]` |
| 8 | reshape：拼接各头 `h × dk = d` | `[B, n, d]` |
| 9 | 输出 `@ W_O`（`[d, d]`） | `[B, n, d]` |

三个要点：

1. **输入输出形状相同**（`[B,n,d]`），所以注意力层可以一层层堆叠。
2. **形状 `[B,h,n,n]` 是内存瓶颈**。它是唯一随 $n^2$ 增长的张量，其余都随 $n$ 线性增长。
3. **批、头维度不参与计算**：矩阵乘法只作用在最后两维，前面的 `B`、`h` 只是“并行做很多份”。

### 一个数值例子

GPT-2 small 的配置：$d=768$，$h=12$，所以 $d_k=64$。取 $B=2$，$n=501$（随手取的数）：

- 输入 X：`[2, 501, 768]`，共 769,536 个数
- 分数表：`[2, 12, 501, 501]`，共 6,024,024 个数，约是输入的 7.8 倍
- 按每个数 2 字节（fp16）算：分数表约 11.5 MiB，输入约 1.5 MiB

序列长度扩大 10 倍（$n=5010$），输入变 10 倍，分数表变约 100 倍，约 1.1 GiB。这就是“长上下文难”的来源。在[形状追踪器](demo/index.html)里拖动 $n$ 可以亲眼看到。

## 第 4 层 · 数学：几个必须理解的点

**① 为什么 `Kᵀ`？**
`Q` 是 `[n, dk]`，`K` 是 `[n, dk]`。要得到 `[n, n]` 的分数表，需要 `[n,dk] × [dk,n]`，所以把 `K` 转置成 `[dk, n]`。分数 $S_{ij}=\sum_{t} Q_{it}K_{jt}$，正是 $q_i\cdot k_j$。

**② 为什么要把头 transpose 到前面？**
矩阵乘法 `@` 只作用于最后两维，前面的维度当作“批”。把 `h` 放到第二维后，`[B, h, n, dk] @ [B, h, dk, n]` 一次就并行算完所有句子的所有头。如果头留在第三维 `[B, n, h, dk]`，就没法直接做这个批量矩阵乘法。

**③ 拆头为什么不增加参数？**
$W_Q$ 是一个 `[d, d]` 的大矩阵。拆成 `h` 个头，等价于把它按列切成 `h` 个 `[d, dk]` 的小矩阵（每个头一个），总参数不变：$h\times d\times d_k=d^2$。多头不是“多花参数”，而是“切开使用”。

**④ 一层注意力的计算量（粗略）**
- 投影 Q/K/V/O：4 个 `[B·n, d] × [d, d]`，约 $4\cdot 2\cdot Bnd^2$ 次浮点运算
- 打分和加权：$2\cdot 2\cdot Bn^2d$ 次

（这里“乘加算 2 次”；取量级即可。）前者随 $n$ 线性，后者随 $n^2$。$n$ 小时前者主导，$n$ 大时后者主导。

## 第 5 层 · 代码

形状标注是读代码最好的注释：

```python
import numpy as np

def multi_head(X, Wq, Wk, Wv, Wo, h):
    B, n, d = X.shape                       # [B, n, d]
    dk = d // h
    def split(M):                           # [B,n,d] -> [B,h,n,dk]
        return M.reshape(B, n, h, dk).transpose(0, 2, 1, 3)
    Q, K, V = split(X @ Wq), split(X @ Wk), split(X @ Wv)
    S = Q @ K.transpose(0, 1, 3, 2) / np.sqrt(dk)   # [B,h,n,n]
    S = S - S.max(-1, keepdims=True)
    A = np.exp(S); A = A / A.sum(-1, keepdims=True) # [B,h,n,n]
    O = A @ V                                        # [B,h,n,dk]
    O = O.transpose(0, 2, 1, 3).reshape(B, n, d)     # [B,n,d]
    return O @ Wo                                    # [B,n,d]
```

这段代码已用 NumPy 2.0.2 实际运行：输出形状为 `[B, n, d]`，且与“逐个头、逐句单独算再拼接”的朴素写法数值一致。完整测试见 [`../attn-07-from-scratch/`](../attn-07-from-scratch/)。

## 练习

**练习 1**：$B=4,n=128,d=512,h=8$。写出 `Q` 做完 reshape 与 transpose 后的形状，以及分数表的形状和元素个数。

**练习 2**：GPT-3 的 $n=2048$，$h=96$。$B=1$ 时，单层分数表有多少个元素？按 fp16 约占多少内存？

**练习 3（找 bug）**：有人写了 `S = Q @ K / np.sqrt(dk)`，`Q`、`K` 都是 `[B,h,n,dk]`。会发生什么？怎么改？

**练习 4**：为什么 `reshape(B, n, h, dk)` 能把头拆开，但把 `reshape(B, h, n, dk)` 直接用在 `[B,n,d]` 上是错的？

### 答案

**练习 1**：`dk = 64`。`Q` 为 `[4, 8, 128, 64]`；分数表 `[4, 8, 128, 128]`，元素个数 $4\times8\times128\times128=524{,}288$。

**练习 2**：$1\times96\times2048\times2048=402{,}653{,}184$ 个元素，约 4.0 亿；×2 字节 ≈ 768 MiB（≈ 0.75 GiB）。

**练习 3**：形状对不上，`[..., n, dk] @ [..., n, dk]` 要求 `dk == n`，通常报错。应写成 `Q @ K.transpose(0, 1, 3, 2)`，即转置最后两维。

**练习 4**：`[B,n,d]` 在内存里是按“词”一个个排的，每个词的 `d` 个数连续。`reshape(B,n,h,dk)` 保持“词”在前，只是把词内的 `d` 个数切成 `h` 份，语义正确；若直接 reshape 成 `(B,h,n,dk)`，会把不同词的数混进同一个“头”，数据被打乱。必须先 reshape 再 transpose。

---

## 易错点

- **softmax 的 axis**：永远是最后一维（被看的词）。
- **reshape 和 transpose 的顺序**：先拆头（reshape），再换轴（transpose）；合并时先换回（transpose），再 reshape。
- **忘了 transpose 回来就 reshape**：形状碰巧对得上，但数据顺序错，不报错、结果错，最难排查。
- **没用 `contiguous`**（PyTorch 中）：transpose 后直接 `view` 会报错，应先 `.contiguous()` 或改用 `reshape`。
