## 前作进展

2017 年末的 NLP 研究有一个尴尬的局面:[Transformer](../05-transformer/01-transformer.md) 刚在机器翻译上击败了所有 RNN baseline,但 NLP 其他任务——分类、阅读理解、自然语言推理、命名实体识别——都各有专门模型,**每个任务从头训一个网络是默认范式**。这造成几个明显问题:

**1. 标注数据稀缺**——情感分类、自然语言推理这些任务的标注数据往往只有几千到几万条,从头训一个深度模型容易过拟合。SQuAD 1.0(2016)算大的也才 10 万条问答对
**2. 模型不通用**——给某个任务训一个 BiLSTM-Attention 模型,完全没法迁移到另一个任务。换任务就要换数据、换网络、换超参,工程成本高
**3. 浪费了海量无标注文本**——互联网上有 TB 级别的自然语言文本,但当时的监督学习范式只能用上其中带标签的极小一部分(≪ 1%)

这条线上前作主要有两类尝试:

**预训练词向量**(Word2Vec 2013, GloVe 2014, FastText 2016)——把"无标注文本"压成"每个词一个向量"。在 RNN 时代是标配,但词向量是**静态的**——"bank"作为"银行"和"河岸"得到同一个向量,且只解决最底层 embedding,上层 RNN 仍要从头训

**上下文相关词表征**——ULMFiT(Howard 2018, AWD-LSTM-based)和 ELMo(Peters 2018, BiLSTM-based)是这条线的两个关键节点。它们都做了"先在 LM 任务上预训练,再迁移到下游"——但 backbone 仍是 LSTM,无法 scale,且预训练任务和微调任务的接口不统一

OpenAI 的 Radford 团队 2018 年 6 月发表的 *Improving Language Understanding by Generative Pre-Training*(GPT-1)做了三件事的组合:

1. **backbone 换成 Transformer**(具体是 decoder-only)
2. **预训练任务用纯生成式语言模型**——自回归地预测下一个 token,不需要任何标注
3. **微调时把所有任务转成"序列输入 → 标签"的统一接口**

这一组合在 12 个标准 NLP benchmark 上拿到 9 个 SOTA,证明了"预训练 + 微调"是一条通用范式。同年 10 月 Google 的 BERT 用 encoder-only + masked LM 给出了双向版本,在 GLUE 上更亮眼,把整个 NLP 社区拖进了"预训练时代"。

## 核心思想

### 直觉:无监督预训练 + 任务微调 + 统一 backbone,替代所有专门架构

理解 GPT-1 真正需要先抓一件事:**2018 年初 NLP 是"每个任务一个专门模型"的范式** — 情感分类用 BiLSTM、阅读理解用 BiDAF、NER 用 BiLSTM-CRF,每换任务就换数据 / 换网络 / 换超参。互联网上 TB 级无标注文本浪费 99% 以上(只有带标签的能用)。OpenAI Radford 2018 反问:**为什么不先用海量无标注文本预训练一个通用 Transformer,再把所有下游任务转成统一序列输入格式,只换最后一层 head 微调?**

三件事必须同时成立才让 GPT-1 在 2018 年成立:

- **Backbone 换成 Transformer(decoder-only)** — 抛弃 ULMFiT / ELMo 的 LSTM,选 [原版 Transformer](../05-transformer/01-transformer.md) decoder 部分;并行训练 + 长依赖建模 + 可 scale
- **预训练任务用纯生成式 LM** — 自回归预测下一个 token,完全无监督,可以用任意文本(BookCorpus 800M token)
- **统一任务接口 + auxiliary LM loss** — 4 类任务(分类 / NLI / 相似度 / 多选)都转成 `<s> ... <$> ... </s>` 序列,微调时加 λ·L_LM 防遗忘

三件事合起来:**12 个 NLP benchmark 上拿到 9 个 SOTA**,证明"预训练 + 微调 + 统一 Transformer backbone"可以替代所有专门架构。同年 10 月 BERT 用 encoder-only + masked LM 在 GLUE 上更亮眼,但**两者验证的是同一范式假设**。这一范式定义了之后 5 年 NLP / LLM 路线 — HuggingFace Transformers 库、所有 fine-tune 工作、decoder-only LLM 主导(LLaMA / Mistral / GPT-4)都源自 GPT-1 这一组合。

![GPT-1 三件套 — Decoder-only + 自回归预训练 + 统一接口](assets/01-gpt1-pretrain-finetune.svg)
*图 1:**上半** 范式革命对比 — 旧范式"每个任务专门模型"(每个任务从头训 BiLSTM/BiDAF,数据稀缺)vs GPT-1 新范式"预训练 + 微调"(一个 Transformer + 海量无标注文本 + task-specific head)。**下半** 完整 pipeline:**Stage 1 预训练** BookCorpus 800M token → decoder-only Transformer 117M → 自回归 LM loss;**Stage 2 微调** 下游任务数据 → 同一 Transformer + linear head + task loss + λ·L_LM auxiliary。底部 callout:统一 backbone + 统一接口让 NLP 从"专门模型时代"进入"预训练时代"。*

### 机制一:Decoder-only Transformer — masked self-attn + GELU + Weight Tying

GPT-1 架构是原版 Transformer 的 **decoder 部分** — 只保留 masked self-attention + FFN,去掉 cross-attention(没有 encoder),layer 数 12,`d_model=768, h=12, d_ff=3072`,总参数 **117M**。

```python
class GPT1Block(nn.Module):
    def forward(self, x):
        # Post-LN(原版风格,GPT-2 后改 Pre-LN)
        x = self.ln1(x + self.drop(self.attn(x)))  # masked self-attn
        x = self.ln2(x + self.drop(self.ffn(x)))   # FFN with GELU
        return x
```

几个被后续 LLM 沿用至今的工程细节:

- **GELU 激活替代 ReLU** — GPT-1 是第一个在 Transformer 里用 GELU 的主流模型,后被 BERT / GPT-2/3/4 全部采用,成为 LLM 默认激活直到 [SwiGLU](../05-transformer/04-rope.md)
- **Weight tying** — LM head 的线性投影和 token embedding 共享权重(Press 2016),把 30%+ 的参数省下来(vocab_size × d_model 这一大块),且在 LM 任务上反而略好
- **Causal mask** — 让位置 t 只能 attend [0, t],实现自回归;这是 decoder-only 选择的根本前提

**选 decoder-only 而非 encoder-decoder 是 GPT 路线的关键判断** — Radford 团队赌"生成式建模 + 单向上下文已经够强",这一赌注在 GPT-2 / GPT-3 后被全面验证,2023+ LLaMA / Mistral / Claude / GPT-4 全部 decoder-only,encoder-decoder 退守到机器翻译等特定场景。

### 机制二:自回归预训练 — 用海量无标注文本

预训练目标就是标准的语言模型最大似然:

$$
\mathcal{L}_{\text{pre}} = -\sum_{t=1}^{T} \log p(x_t | x_{t-k}, \ldots, x_{t-1}; \theta)
$$

k=512 是上下文窗口,θ 是 Transformer 参数。这就是 Bengio 2003 NPLM 的现代化版本 — **用 Transformer 替代 MLP,用大语料替代小数据**。

**关键数据选择:BookCorpus 而非 Wikipedia**。论文特别强调用 7000 本未发表小说(800M token)的原因 — **长程依赖更丰富**。小说里一个伏笔可以隔几页才有回应,迫使模型学"看到 t-500 位置的语义结构"的能力;Wiki 文章短、独立,长依赖弱。这一"用数据形态驱动模型能力"的思想后来被 GPT-2 / GPT-3 推到极致(WebText / Common Crawl)。

**预训练硬件**:8 × P6000 × 30 天。117M 参数 + 800M token,现代标准下是非常小的训练量,但 2018 年算"大规模实验"。这个量级今天单卡几小时就能训完 — 让所有人意识到"预训练成本不是门槛,只要做对架构 + 数据"。

### 机制三:统一任务接口 — 所有任务转成序列输入

GPT-1 真正的工程贡献是**把所有 NLP 任务转成统一的序列输入格式**,让同一个预训练模型适配几乎任何任务,只换最后一层 head。论文给出 4 种格式:

| 任务类型 | 输入格式 |
|---|---|
| **分类**(单句) | `<s> 文本 </s>` → linear classifier |
| **NLI**(句对) | `<s> 前提 <$> 假设 </s>` → 分类 |
| **句子相似度**(对称) | `<s> A <$> B </s>` + `<s> B <$> A </s>`,两次 forward 求和 |
| **多项选择**(QA) | 每个候选 c_i:`<s> 文档+问题 <$> c_i </s>`,N 次 forward 后 softmax |

核心 trick 是 **`<s>` / `<$>` / `</s>` 三个特殊 token** — 分别标记开始 / 字段分隔 / 结束。Transformer 把它们当普通词处理,但任务特定的"哪个位置代表什么"被显式编码进序列。**模型本身没有任何任务特定模块,微调时只多一个 linear head**。

**微调目标**用 LM auxiliary loss 联合:

$$
\mathcal{L}_{\text{ft}} = \mathcal{L}_{\text{task}} + \lambda \cdot \mathcal{L}_{\text{LM}}, \quad \lambda = 0.5
$$

加 LM loss 是**防 catastrophic forgetting 的早期工程解** — 防止微调时模型"忘掉"预训练学到的通用语言能力。这一技巧后被 ULMFiT / BERT / GPT-2 全部采用。

更深远的意义:GPT-1 的"任务统一接口"思想直接预示了 GPT-3 的 **in-context learning** — 任务描述 + 例子全部用自然语言写在 prompt 里,**连 task-specific head 都不要**。从这角度,**GPT-3 就是 GPT-1 接口的极端化**。

### 三件套协同:Decoder + LM 预训练 + 统一接口 缺一不可

GPT-1 在 2018 年开启 NLP 预训练时代,**不是单一改进**,而是三件套同时调到协同点 —— 任何一个抽掉 GPT-1 都不成立,这一点和 [ResNet](../01-cnn/05-resnet.md) 的 `shortcut + BN + He 初始化` 协同关系一致:

- **只有 LM 预训练 + 统一接口,没有 Transformer backbone** — 用 LSTM(ULMFiT 路线)只能 scale 到 ~100M 参数就饱和,长依赖建模差;GPT-1 的成功本质上靠 Transformer 的并行 + 长程能力
- **只有 Transformer + 统一接口,没有自回归 LM 预训练** — 没有大规模无监督学习,所有任务从随机初始化训练,12 个 benchmark 不可能拿 9 个 SOTA;预训练是"以无标注海量数据填补标注数据稀缺"的核心
- **只有 Transformer + LM 预训练,没有统一任务接口** — 每个下游任务还是需要专门的网络结构(各种 task-specific 模块),"一个模型适配所有任务"的卖点不成立,工程上无法成为通用范式

三件套合起来才让 NLP 在 2018 年从"专门模型时代"跨入"预训练时代"。同年 BERT 用 encoder-only + masked LM 验证了双向版本,两条路线竞争 5 年后,**decoder-only 路线最终在 GPT-3 / LLaMA / GPT-4 时代胜出** — encoder-only 主要留在 BERT-family 的 retrieval 等场景。但 GPT-1 真正的历史功绩不在"赢得路线之争",而在**第一次系统证明"预训练 + 微调"是 NLP 的通用范式**,这一范式至今(2024)仍是 LLM 训练的基础(只是 fine-tune 换成 RLHF / DPO)。

![GPT-1 vs BERT 路线对比 + 影响后续 LLM 路线](assets/01-gpt1-paradigm-shift.svg)
*图 2:**上半** GPT-1(decoder-only,自回归 LM)vs BERT(encoder-only,masked LM)2018 同年两条路线对比 — 架构 / 训练目标 / 微调方式 / 适合任务 4 个维度差异。**下半** 2018 → 2024 LLM 路线演化 — GPT-1 117M → GPT-2 1.5B → GPT-3 175B(in-context learning,统一接口的极端化)→ LLaMA / Mistral / GPT-4(decoder-only 全面主导)。底部 callout:GPT-1 的"统一任务接口"思想在 GPT-3 时代演化成 "prompt = 任务描述 + 例子",**连 task-specific head 都不需要**。*

12 个任务里 9 个 SOTA(论文统计口径),最显著的提升是**长上下文推理类**(QNLI / Story Cloze / RACE)——这正好印证了 BookCorpus 长程依赖训练的价值。失利的几个(RTE / MRPC)是小数据任务(几千条),论文里也承认 GPT-1 在数据极少时不如专门的 BiLSTM 模型。

但 GPT-1 的真正意义不在这些数字,而在**它证明了一个方法论假设**:无监督预训练 + 任务微调 + 统一 Transformer backbone,可以替代当时所有 NLP 任务的专门架构。这一假设在 4 个月后被 BERT 用更激进的方式(更大模型 + 双向 MLM)进一步验证,从此 NLP 的研究范式被永久改变。

## 训练细节

| 维度 | GPT-1 |
|------|------|
| 架构 | 12 层 decoder-only Transformer, `d_model = 768, h = 12, d_ff = 3072`, GELU 激活, 117M 参数 |
| 上下文窗口 | 512 token |
| Tokenization | BPE,40K 词表 |
| 预训练数据 | BookCorpus,800M token |
| 预训练优化器 | Adam, lr=2.5e-4, warmup 2000 步后 cosine 衰减到 0 |
| 预训练 batch | 64 序列 × 512 token = 32K token / batch |
| 预训练时间 | 8 × P6000 × 100 epoch ≈ 30 天 |
| 微调 lr | 6.25e-5(比预训练小 4 倍,经典"小 lr 微调"做法) |
| 微调 epoch | 通常 3,小任务多到 10 |
| LM auxiliary loss 系数 | λ = 0.5 |
| Dropout | 0.1 |
| Position encoding | learned absolute(不是正余弦,和 BERT 一致;后来被 [RoPE](../05-transformer/04-rope.md) 取代) |

注意 GPT-1 用 **learned PE 而不是正余弦**——原版 Transformer 论文比较过两种,效果差不多,GPT-1 选了 learned PE 是因为实现略简单。BERT 也是 learned PE。直到 [RoPE](../05-transformer/04-rope.md) 出现,learned PE 才被淘汰。

## 关键代码

GPT-1 的 decoder-only block,几乎就是原版 Transformer encoder block + causal mask:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class GPT1Block(nn.Module):
    def __init__(self, d_model, num_heads, d_ff, dropout=0.1):
        super().__init__()
        self.attn = MaskedMultiHeadAttention(d_model, num_heads)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),                            # ← 不是 ReLU
            nn.Linear(d_ff, d_model),
        )
        self.ln1 = nn.LayerNorm(d_model)
        self.ln2 = nn.LayerNorm(d_model)
        self.drop = nn.Dropout(dropout)

    def forward(self, x):
        # Post-LN(原版风格,GPT-2 之后改为 Pre-LN)
        x = self.ln1(x + self.drop(self.attn(x)))
        x = self.ln2(x + self.drop(self.ffn(x)))
        return x

class GPT1(nn.Module):
    def __init__(self, vocab_size, max_len=512, d_model=768,
                 num_heads=12, num_layers=12, d_ff=3072):
        super().__init__()
        self.tok_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_len, d_model)  # learned PE
        self.blocks = nn.ModuleList([
            GPT1Block(d_model, num_heads, d_ff) for _ in range(num_layers)
        ])
        self.ln_f = nn.LayerNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
        # 关键:weight tying — LM head 和 token embedding 共享权重
        self.lm_head.weight = self.tok_emb.weight

    def forward(self, x):
        # x: [B, T] token ids
        B, T = x.shape
        pos = torch.arange(T, device=x.device)
        h = self.tok_emb(x) + self.pos_emb(pos)
        for block in self.blocks:
            h = block(h)
        h = self.ln_f(h)
        logits = self.lm_head(h)  # [B, T, vocab_size]
        return logits

def causal_mask(T):
    """生成 [T, T] 下三角 mask:位置 t 只能看 [0, t]"""
    return torch.tril(torch.ones(T, T)).bool()
```

两个工程要点:

- **GELU 激活而不是 ReLU** —— GPT-1 是第一个在 Transformer 里用 GELU 的主流模型。GELU 的论文(Hendrycks 2016)证明它在 NLP 任务上略优于 ReLU,GPT/BERT 全部采用,后来成为 LLM 默认激活直到 [SwiGLU](../05-transformer/04-rope.md)
- **Weight tying** —— LM head 的线性投影 `W_{lm}` 和 token embedding `W_{emb}` 共享权重(Press 2016)。这把 30%+ 的参数省下来(`vocab_size × d_model` 这一大块),且在标准 LM 任务上反而略好

## 影响 / 后续

GPT-1 在历史上的位置很特殊——**它单独看影响不大**(同年 BERT 在 GLUE 上更亮眼,把它抢了风头),但**它确立的范式定义了之后 5 年的 LLM 路线**。具体几条线:

**1. "预训练 + 微调"成为 NLP 默认范式**——2018 之后所有任务都从 BERT/GPT 预训练权重起步,从头训成为例外。HuggingFace 的 Transformers 库就是为这个范式服务的工程化产物

**2. Decoder-only Transformer 路线**——GPT-1 选 decoder-only 在 2018 是非主流选择(BERT 双向更亮眼)。但生成式建模的通用性在 [GPT-2](02-gpt2.md) / [GPT-3](03-gpt3.md) 后被全面验证,decoder-only 成为 LLM 默认架构。今天 LLaMA / Mistral / Qwen 全是 decoder-only

**3. 任务统一接口的种子**——GPT-1 的"所有任务转成序列输入"思想直接预示了 [GPT-3](03-gpt3.md) 的 in-context learning(任务描述 + 例子全部用自然语言写在 prompt 里)。从这个角度,GPT-3 就是 GPT-1 任务接口的极端化——连 task-specific head 都不要,任务完全用自然语言描述

**4. Weight tying / GELU / 联合 LM loss 等具体工程细节**被几乎所有后续 LM 沿用

GPT-1 的局限也很明确,这些局限推动了后续节点的方向:

- **117M 参数 + 800M token 还是太小**,zero-shot 能力几乎为 0 → [GPT-2](02-gpt2.md) 推到 1.5B + 40B token
- **仍然需要任务微调**——每个任务还是要标注数据 → [GPT-3](03-gpt3.md) 用 in-context learning 消除微调依赖
- **Scaling 关系未知**——加规模会不会一直 work?最优 N/D 配比是什么? → [Scaling Laws](04-scaling-laws.md) 节点
- **Post-LN + 正余弦/learned PE + ReLU/GELU FFN 是 2018 配方** → 2023 LLaMA 全套换成 Pre-RMSNorm + [RoPE](../05-transformer/04-rope.md) + SwiGLU,见 [05-gpt4-llama.md](05-gpt4-llama.md)
